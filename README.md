# Описание проекта: Поиск максимального значения в большом массиве данных

Данный проект представляет собой практическую реализацию алгоритма поиска максимального значения в слайсе целых положительных чисел с использованием двух подходов: **однопоточного** (линейный проход) и **многопоточного** (разбиение на части с параллельным вычислением). 
Основная цель — продемонстрировать преимущества конкурентного выполнения в Go на примере обработки больших объёмов данных.



## Актуальность и контекст

Обработка крупных массивов данных (от миллионов элементов) — частая задача в бэкенд-разработке, аналитике и системах реального времени. При работе с такими объёмами даже простая операция, как поиск максимума, может стать узким местом, если выполняется последовательно. 
Использование горутин позволяет эффективно задействовать многоядерные процессоры и сократить время выполнения за счёт параллельной обработки независимых фрагментов данных.



## Цель работы

1. Написать программу на Go, которая генерирует слайс случайных положительных чисел заданного размера.
2. Реализовать два способа поиска максимального элемента:
   - классический последовательный (`maximum()`),
   - параллельный с разбиением на фиксированное число частей (`maxChunks()`).
3. Сравнить время выполнения обоих подходов (в микросекундах) и убедиться в ускорении при использовании горутин.
4. Обработать все краевые случаи (пустой слайс, слайс с одним элементом, нулевой размер и т.д.) для обеспечения надёжности программы.
5. Покрыть ключевые функции модульными тестами.


## Функциональные требования

### 1. Генерация данных (`generateRandomElements`)
- **Вход**: размер слайса (`int`).
- **Выход**: слайс целых положительных чисел.
- **Особенности**:
  - При размере `≤ 0` возвращается пустой слайс (без паники).
  - Для генерации используется `math/rand`.
  - Тестируется на корректность размера и типов значений.

### 2. Однопоточный максимум (`maximum`)
- **Вход**: слайс целых чисел.
- **Выход**: максимальное значение (тип `int`).
- **Краевые случаи**:
  - Пустой слайс → возвращаем `0` (или минимальное допустимое значение, выбираем 0, т.к. числа положительные).
  - Слайс из одного элемента → возвращаем этот элемент.
- **Тесты**: проверка на пустой слайс, слайс с одним элементом, стандартный случай.

### 3. Многопоточный максимум (`maxChunks`)
- **Вход**: слайс целых чисел.
- **Выход**: максимальное значение среди всех элементов.
- **Алгоритм**:
  1. Слайс делится на `CHUNKS` (константа, равна 8) равных (или почти равных) частей.
  2. Для каждой части запускается отдельная горутина.
  3. Каждая горутина находит максимум в своей части и сохраняет результат в общий слайс результатов.
  4. Используется `sync.WaitGroup` для синхронизации.
  5. После завершения всех горутин находится максимум среди полученных восьми значений.
- **Особенности**:
  - Учитывается случай, когда элементов меньше, чем `CHUNKS` — тогда части могут быть пустыми, но горутины корректно обрабатывают этот сценарий.
  - Все горутины запускаются в цикле, индексы вычисляются динамически.
- **Тесты**: проверяются корректность результата на разных размерах слайса, включая граничные.


## Главная функция (`main`)

1. Задаётся константа `SIZE` (например, 10 000 000).
2. Вызывается `generateRandomElements(SIZE)` для создания исходного слайса.
3. Замеряется время (с помощью `time.Now()` и `time.Since()`) выполнения `maximum()`.
4. Замеряется время выполнения `maxChunks()`.
5. Результаты (значения максимумов и время в микросекундах) выводятся в консоль.
6. Все крайние случаи обрабатываются на всех уровнях.

## Технические детали реализации

- **Пакет**: `main`.
- **Генерация случайных чисел**: `rand.Intn(1000)` — для простоты диапазон ограничен, но может быть любым.
- **Константы**: `CHUNKS = 8`, `SIZE = 10_000_000` (настраиваются).
- **Параллелизм**:
  - Используются анонимные функции, запускаемые как горутины.
  - `WaitGroup.Add(CHUNKS)` и `WaitGroup.Done()` внутри каждой горутины.
  - Для доступа к слайсу результатов используется индексация, блокировки не требуются, так как каждая горутина пишет в свою уникальную ячейку.
- **Измерение времени**: в микросекундах (`duration.Microseconds()`).



## Ожидаемые результаты

При достаточно большом размере слайса (например, 10 млн) многопоточный вариант должен выполняться быстрее однопоточного примерно в 4–8 раз (в зависимости от количества ядер процессора). Это наглядно демонстрирует эффективность конкурентных вычислений для задач, допускающих естественное разбиение на независимые подзадачи.



## Примечания по тестированию

- Тесты написаны с использованием стандартного пакета `testing`.
- Проверяются:
  - корректность генерации (длина слайса, положительность чисел);
  - правильность нахождения максимума в различных сценариях;
  - поведение функций при пустом слайсе или размере, меньшем чем `CHUNKS`.
- Тесты можно запускать с флагом `-race` для выявления возможных состояний гонки.



## Заключение

Данный проект служит наглядным примером применения многопоточности в Go для ускорения вычислительных задач. Он закрепляет навыки работы с горутинами, каналами (здесь не используются, но подразумеваются), синхронизацией через `WaitGroup`, обработкой ошибок и тестированием. Полученные результаты могут быть использованы для дальнейшего изучения более сложных паттернов параллельной обработки данных.
